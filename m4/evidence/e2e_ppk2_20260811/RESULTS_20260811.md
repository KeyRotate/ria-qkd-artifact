# Cortex-M4 RIA-QKD End-to-End Handshake PPK2 Recaptures (2026-08-11)

Re-run of the end-to-end STM32F407G-DISC1 handshake over the public FRP path
(Dell CP2102 USART2 115200 baud -> frp.vivon1031.top:36012 -> NUC RIA-QKD server,
same configuration as 2026-08-07). Three power cycles, one handshake per boot,
each captured on the Nordic PPK2 (source-meter, 3.3 V, 100 kHz, PA5-delimited).

Server: `ria_server.py` on the NUC (same protocol code as 2026-08-07; only the
connection EOF handling was hardened for unattended re-runs), provisioned from
`/tmp/ria_provision` (client static pk, server sig sk, shared anchor).

On the M4 side, all three runs report accepted=1, done=1 from the results frame
(magic 0x48415348 + cycles + accepted + done). This verifies the server
Finished tag on-device and shows that the client completed its decapsulation
and session-key path under the provisioned static key and anchor. It is
indirect interoperability evidence; no standalone ss1/ss2/ss3 comparison
file is included here. The M4-side DWT window is authoritative for handshake
duration and matches the PA5-delimited power window to within a few
milliseconds.

PROVENANCE NOTE (server-side): the server observed each handshake as OK during
the 2026-08-11 re-capture, but no matching server-side log for this session was
archived in this directory. The archived server-side `handshake OK` log with
N=30 latency statistics is the separate 2026-08-07 run (see `../e2e_logs/`).
The accepted=1/done=1 frames provide indirect interoperability evidence only;
no standalone ss1/ss2/ss3 comparison file or independent server-confirmed
byte-level comparison is included in this archive.

Energy scales with handshake duration (~110-115 mA average current).

CALIBRATION NOTE: the PA5 durations and DWT cycle counts above are reproduced
from the raw `.bin` traces. The absolute current (mA) and energy (mJ) values
depend on PPK2 device-specific calibration modifiers read from the live device
at analysis time, which are not stored in the archived `.bin` files; the
reported averages/energies are internally consistent with avg_current x V x
duration but are not independently reproducible from the archive alone. See
`ppk2_analyze.py`.

## Files

- `ppk2_capture{1,2,3}.bin` - raw PPK2 power traces (100 kHz, 3.3 V)
- `relay_serial_run{1,2,3}.bin` - raw serial stream captured at the relay,
  including the M4 results frame (magic 0x48415348 + cycles + accepted + done)
- `ppk2_analyze.py` - PA5 pulse analysis (duration / avg / peak / energy)
- `parse_results_frame.py` - results-frame parser
- `SHA256SUMS` - file hashes
